---

## 2. 核心測試劇本 (Test Scenarios)

### 🧪 情境 A：一般生產 BOM 建立與簽核
*   **測試目的**：驗證一般無風險的 BOM 單能順利由直屬主管核准並結案。
*   **操作步驟**：
    1. 使用 **`EMP001` (林員工)** 登入，建立一張 **台南廠 (TNN)** 的 BOM 單。
    2. 填寫物料 `M-CPU-INTEL`，數量 `10`。不要勾選高風險或成本影響。
    3. 點擊提交，確認狀態變為 `APPROVING`。
    4. 改用 **`PM-TNN` (台南生產主管)** 登入。
    5. 在待簽核清單找到該單據，點擊「同意」。
*   **預期結果 (Expected)**：
    *   `PM-TNN` 簽核後，系統提示成功，畫面不會卡頓（背景處理同步）。
    *   單據狀態自動變為 `CLOSED`（若會計同步成功）。
    *   `GM-TNN` 與 `FIN-TPE` 的清單中**不該**出現此單據。

### 🧪 情境 B：高風險 BOM 單加簽 (High Risk)
*   **測試目的**：驗證勾選高風險旗標後，系統會正確產生三關簽核。
*   **操作步驟**：
    1. 用 **`EMP001`** 建立 BOM，勾選 **「包含高風險物料」**，提交。
    2. 用 **`PM-TNN`** 登入並同意。
    3. 用 **`GM-TNN`** 登入並同意。
    4. 用 **`FIN-TPE`** 登入並同意。
*   **預期結果 (Expected)**：
    *   必須嚴格按照 `生產主管 -> 廠區主管 -> 台北財務` 的順序簽核。
    *   前面的人未簽核前，後面的人（例如 `FIN-TPE`）無法看到該單據或進行簽核。

### 🧪 情境 C：跨廠物料轉移 (雙向調撥)
*   **測試目的**：驗證台南轉高雄的物料轉移，會經過雙方倉庫主管。
*   **操作步驟**：
    1. 用 **`EMP001`** 建立物料轉移，來源：`台南廠`，目標：`高雄廠`。
    2. 物料填寫 `M-GPU-NVIDIA`，數量 `10`。提交。
    3. 依序使用 **`WH-TNN` (台南倉管)** ➔ **`WH-KHH` (高雄倉管)** ➔ **`FIN-TPE` (台北財務)** 登入並同意。
*   **預期結果 (Expected)**：
    *   提交瞬間，系統 Log 應顯示 ERP 已預占 (Reserve) `10` 個該物料。
    *   最後一關 `FIN-TPE` 簽核後，系統 Log 應顯示 ERP 正式扣除 (Deduct) 該物料。
    *   單據最後狀態為 `CLOSED`。

### 🧪 情境 D：廠區內物料調撥
*   **測試目的**：驗證同廠區轉移不需要驚動他廠主管。
*   **操作步驟**：
    1. 用 **`EMP001`** 建立物料轉移，來源與目標廠區皆選 **`台南廠`**，但倉庫名稱不同。
    2. 提交簽核。
*   **預期結果 (Expected)**：
    *   簽核路徑只會產生兩關：**`WH-TNN` (台南倉管)** ➔ **`FIN-TPE` (台北財務)**。
    *   **不會**出現 `WH-KHH` 關卡。

### 🧪 情境 E：系統防呆與自動駁回 (Auto-Reject)
*   **測試目的**：驗證不合理的單據會被系統直接擋下。
*   **操作步驟與預期結果**：
    *   **測項 1 (庫存不足)**：申請轉移數量大於 ERP 現有庫存（例如輸入數量 999999）。提交時，狀態直接變為 `REJECTED`，並顯示「庫存不足」。
    *   **測項 2 (物料停用)**：使用 `M-DEPRECATED` (系統預設已停用的物料) 申請轉移。提交時，狀態變為 `REJECTED`，顯示「物料已停用」。
    *   **測項 3 (來源與目標相同)**：轉移單的來源廠區與目標廠區相同，且倉庫名稱也一模一樣。提交會被直接阻擋。

### 🧪 情境 F：撤回單據與庫存釋放 (Cancel & Release)
*   **測試目的**：驗證申請人撤回單據時，能正確釋放被預占的 ERP 庫存，避免死庫。
*   **操作步驟**：
    1. 用 **`EMP001`** 建立跨廠轉移單，物料數量填 `50`。提交簽核。
    2. 不要讓主管簽核。用 **`EMP001`** 進入該單據，點擊「撤回 (Cancel)」。
*   **預期結果 (Expected)**：
    *   單據狀態變為 `CANCELED`。
    *   系統 Log 顯示 `[ERP 庫存釋放] 釋放=50`。
    *   再次發起另一張單據時，可用庫存應恢復正常。

## 3. 驗收完成標準 (Acceptance Criteria)

- [ ] 表單介面均能防呆（如漏填必填欄位時無法點擊提交）。
- [ ] 所有不同情境（A~G）的簽核路徑 (Approval Steps) 皆與上述預期 100% 吻合。
- [ ] 權限越界操作（如拿 PM 帳號去簽 WH 的關卡）會回傳錯誤提示，且無法成功。
- [ ] 最終一關簽核按下同意時，介面能迅速反映（秒回），無阻塞感。
- [ ] 後台可正常查閱每一張單據的完整歷史軌跡 (Approval Logs)。
